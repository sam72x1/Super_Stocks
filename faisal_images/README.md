# 📸 صور منهجية فيصل — مجلد المراجعة الشاملة

## ⚡ الأسرع: **أرسلها للبوت بالتلغرام** (دفعة واحدة · بلا ضغط · بلا موقع)
1. افتح محادثة **بوت الارتكاز** بالتلغرام.
2. **حدّد كل الصور** من الاستوديو ← **إرسال**. (تلغرام يقسّمها ألبومات تلقائيًّا —
   لكنها **حركة واحدة منك**.) 💡 الإرسال «كملف/Document» يحفظ حدّة النص واسم الملف
   (`IMG_0153.jpeg`) — والصورة المضغوطة تُقرأ عادةً أيضًا.
3. قل لي «أرسلتها» — أُشغّل workflow **📥 اسحب صور التلغرام إلى المستودع** فيسحبها
   إلى `faisal_images/` ويحدّث سجلّ التغطية ويدفعها، ثم أبدأ القراءة بالدفعات.

⏱️ **مهم:** تلغرام يحفظ التحديثات **~24 ساعة**، فقل لي بعد الإرسال ولا تؤجّله أيامًا.

---

## البديل: رفع مباشر بواجهة GitHub
1. افتح المستودع على GitHub ← مجلد `faisal_images/`.
2. **Add file ← Upload files** ← اسحب الصور (دفعات كبيرة مقبولة).
3. **Commit**. خلاص — أقرأها من المستودع مباشرةً بلا إرسال بالمحادثة.

## التسمية (مهمة للتتبّع)
- الأفضل **إبقاء اسم الصورة الأصلي** لو فيه رقم: `IMG_0153.jpeg` ← الرقم هو المعرّف.
- بلا رقم؟ سمِّها `NEW_<أي وصف>.jpeg` — الأداة تُدرجها بمعرّف من اسم الملف.
- التكرار غير مضرّ: الأداة تُميّز الصورة المكرّرة ببصمة المحتوى (SHA-256).

## ما تفعله الأداة (`image_audit.py`)
تُنتج **سجلّ تغطية** (`FAISAL_IMAGE_AUDIT.md` + `faisal_image_audit.json`) يقول لكل صورة:
- **📗 موثّقة** — رقمها مذكور في `FAISAL_IMAGES_CATALOG.md` أو `CLAUDE.md`/`HANDOFF.md`.
- **📕 غير موثّقة** — لم تُقرأ بعد ⇒ **هذي التي نحتاج نمرّ عليها**.
- والحالة اليدوية التي أُدخلها بعد قراءة كل دفعة: `implemented` / `confirmed` /
  `rejected` / `open` مع سطر السبب — فلا تضيع صورة ولا يُعاد عمل تمّ.

## لماذا لا يوجد «موقع» يستقبل الصور
الصور تصلني بطريقتين فقط: هذي المحادثة، أو المستودع. **أي صفحة أنشرها لا تستطيع
تمريرَ الصور إليّ** (صفحة ثابتة معزولة، ولا خادم دائم لي). فالمستودع هو المسار
الحقيقي — وهو أفضل أيضًا: دائم، مرقَّم، وقابل للتتبّع.

## بعد الانتهاء
الصور نفسها قابلة للتقليم لاحقًا (الحجم)؛ **القواعد المستخرجة والسجلّ يبقيان دائمًا**
في الكاتالوج والذاكرة.

## ⚡ الطريق الأسرع: **ZIP واحد على Release** (دفعة واحدة حقيقية)
**مُثبَت بالقياس اليوم:** متوسط صورك **411 كيلوبايت** ⇒ 300 صورة ≈ **123 ميغا**.
وواجهة GitHub تسقف الرفع المباشر بـ**100 ملف لكل رفعة** و**25 ميغا للملف** —
أما **أصل الإصدار (Release asset) فيسمح حتى 2 غيغا للملف الواحد**. واختبرتُ التنزيل:
`releases/download/...` يرجع **HTTP 200** من بيئتي ✅.

**الخطوات (مرة واحدة):**
1. اضغط كل الصور في ملف واحد `faisal_images.zip`.
2. بالمستودع: **Releases ← Draft a new release** ← وسم مثل `images-v1`.
3. **Attach binaries** ← ارفع الـZIP ← **Publish release**.
4. قل لي «الصور جاهزة» — أنزّلها وأفكّها وأبدأ القراءة بالدفعات.

**ميزتان:** رفعة واحدة فعلًا · و**الصور لا تدخل تاريخ git** فلا يتضخّم المستودع
(الـ123 ميغا تبقى بالتاريخ للأبد لو رُفعت داخل المجلد).

## الطريق البديل: رفع مباشر للمجلد
يعمل أيضًا، لكنه **3 رفعات** (سقف 100 ملف لكل رفعة) وتدخل الصور تاريخ git.

## أمر الاستخراج عندي (للمرجع)
```
curl -sSL -o /tmp/f.zip "<رابط أصل الإصدار>" && unzip -o -q /tmp/f.zip -d faisal_images/
python3 image_audit.py
```
